# Audit — 2026-08-06

Three independent reviewers, no prior context on the build, each pointed at a
different surface so their blind spots would not overlap: the newest code, money
correctness, and operational failure modes. All read-only. All required to
**demonstrate** a finding, not assert it — most HIGH findings below arrived with
a runnable script that produced the wrong outcome against the real modules.

Every finding is fixed, with a spec that fails against the old behaviour, unless
marked ACCEPTED. Suite: **292 specs**, up from 285 at audit start.

## Why this exists

This repo's premise is that prose rots and duplicates grow unseen, so the code
is pinned by numbered invariants (`SPEC.md`) and a spec suite. Audits test the
premise itself: *does the suite pin what it claims?* Seven of the findings below
were invisible to a green suite, and **six specs asserted the wrong thing** —
including one that encoded a bug as expected behaviour. That is the most
valuable result here; a suite you trust without checking is a suite that has
stopped working.

## HIGH — fixed

| # | Finding | Fix |
|---|---|---|
| 1 | **A degraded read was treated as a fact.** An empty positions list (venue under load, account-type mismatch) is indistinguishable from genuinely flat — and the engine took the *irreversible* branch on one such read: killed the bot, cancelled every order, wrote a tombstone, reported "position flat" while the real position lived on, order-less. *Demonstrated.* | **E9**: flat is confirmed across consecutive reads before any stand-down |
| 2 | **Unknown equity read as zero.** A hollow wallet payload yielded `equity = 0.0`, which is below every `account_equity` stop level — one degraded read would flatten and kill every equity-stopped bot in the fleet. *Demonstrated.* | **E9**: unknown equity is `None` and fires nothing |
| 3 | **A liquidation looked like a take-profit.** A martingale treated *any* flat transition as "round complete"; with `repeat: true` it re-entered immediately — walking back into whatever had just liquidated it, with the cooldown anchored to the liquidation fill as if it were a TP. | **M14**: the venue's account of the closing fill decides; anything but our own exit stands the bot down |
| 4 | **Forced closes were invisible.** `BustTrade` (liquidation) and `AdlTrade` (auto-deleveraging) were dropped by an `execType == 'Trade'` filter, so liquidations never entered the ledger *or* the reinvest calculation — a wiped-out bot would size its next round as if the loss never happened. *Demonstrated.* | **R8**: a forced close is a fill |
| 5 | **A restart mid-round re-armed filled rungs.** The martingale's round anchor was process memory; on restart the plan re-anchored on *average entry*, deepening every remaining safety price and un-suppressing rungs that had already filled — deploying past the capital the validator approved, repeatably. *Demonstrated with numbers.* | **M15**: the anchor is recovered from the venue by inverting a resting rung's own price |
| 6 | **Total loss re-entered at full size.** A reinvest factor of exactly `0.0` (capital fully consumed) is falsy, so both call sites substituted `1.0` — the one state where the shrink rule should stop trading was the one state it placed full-size orders. *Demonstrated.* | **M12**: zero is a real factor and refuses the round |
| 7 | **A fired tranche resurrected.** "Passed" was measured against the *current* mark, so a filled tranche re-entered the target set whenever price retreated below it, churning the conditional book on every oscillation. *Demonstrated.* | **M10**: passed is monotone against the best mark the round has seen |
| 8 | **The alert channel could wedge itself permanently.** The coalescing buffer had no size cap; one outage could grow it past the messaging limit, after which *every* send failed forever — silently, including kill pages. *Demonstrated: zero pages delivered after recovery.* | oversize payloads send the newest lines and state what was dropped; a poisoned buffer is never retained |
| 9 | **P&L summed two currencies.** The fleet total added inverse base-coin realized to linear quote-coin realized — SPEC A4's "units never mix" recurring in the summary line. *Verified numerically.* | the total is quote-only and says so; inverse books are reported per-row at mark |

## MED — fixed

- **One bot's venue trouble starved the fleet.** A single raising bot ended the
  cycle for every bot after it in the list — their stops went unevaluated, with
  only a staleness page ~17 minutes later. Now each bot's cycle is isolated.
- **Locks lived in `/tmp`.** systemd-tmpfiles deletes files there after ~10
  days regardless of held locks, so a long-running fleet silently lost the
  "one process per account" guarantee (F3). Locks moved beside the logs.
- **Ambiguous market writes could double-fire.** A seed or martingale base
  order whose response was lost would be re-placed next cycle — doubling
  inventory. Now assumed placed, per E6, and reconciled by the next truth read.
- **The reinvest window could scale on a phantom.** A 30-day window slicing
  mid-round produced a phantom opposite position and a garbage factor. The
  truncation check that the readout already had is now applied here too.
- **The fee floor was calibrated for perps only.** Spot charges roughly ten
  times a perp per side, so the 0.1% floor allowed spot exits that lose money
  after a round trip. The floor is now venue-shaped (G6).
- **B8 was never wired.** "Spacing must clear the guard band" existed as a
  tested pure function with no call site, so a too-tight grid churned forever
  with no warning. Now checked at build against live quotes.
- **Inverse min-notional used the wrong denomination** (inverse qty *is* USD
  notional); **the preflight probe could crash the whole build** on an
  instrument with no min-notional, and could strand its rehearsal order on an
  unexpected cancel error.
- **The backtester lost inventory.** Float subtract-then-floor dropped a whole
  qty-step per iteration — the exact hazard the live exit ladder was fixed for
  in slice 3, never ported to the backtester. It now counts in integer steps.

## ACCEPTED — documented, not fixed

- **The snapshot reports the bot's belief, not the venue.** A dead or halted
  bot freezes its last known position, so watchdog position-bounds cannot see a
  residue left by a partial flatten. Accepted for now: the kill event states the
  residue explicitly and the range review reads venue truth daily. Revisit
  before real funds.
- **`mark_price` falls back to last trade** when a venue omits the mark. Now
  flagged in truth (`mark_is_mark`) so a future slice can refuse to fire a stop
  on a wick print rather than silently substituting.
- **Telegram credentials are optional and silent.** A mistyped token makes every
  layer "succeed" while paging nobody. A startup end-to-end test page is the
  obvious fix and is not yet built.

## Infrastructure hardening — reviewed separately, findings withheld

Host and deployment hardening was audited in the same pass. **Those findings are
deliberately not published**: a public description of a specific machine's
posture is a map for whoever reads it. Nothing about the box appears in this
repo, by rule.

What anyone running this should check on their own machine — a short version of
the same review:

- SSH: key-only, passwords disabled, root login off or key-only, and know which
  keys are authorised.
- Firewall: default-deny inbound; expose only the ports you actually use.
- Brute-force protection (fail2ban or equivalent) actually running, with a jail
  for SSH.
- Unattended security upgrades enabled — **and reboot** when a kernel is staged;
  patched-but-not-rebooted is unpatched.
- Secrets: mode `0600`, owned by the service user, never in git. Sweep your own
  repo history for keys, not just the working tree.
- No unused shell accounts; least privilege for anything the box stores — if a
  credential is not needed for a job running there, it should not be there.
- Log rotation, so an unattended fleet cannot fill its own disk.

An agentic CLI in a read-only configuration is a good way to run that checklist
periodically; `ops/triage-settings.json` in this repo is a ready-made read-only
cage you can point at your own box.

## What this changes about the build

1. **Audit before promotion, not after.** The evidence gate in
   `PROMOTION.md` now assumes a fresh multi-reviewer audit against the code as
   it will actually run.
2. **A green suite is a claim, not a proof.** Six specs asserted the wrong
   thing. Sabotage specs (T1) catch a *removed* guard; they do not catch a guard
   that was never wired, or a spec written from the same misunderstanding as the
   code. Independent readers do.
3. **The dangerous class is "irreversible action from a single ambiguous
   signal."** Findings 1, 2 and 3 are the same bug wearing three coats. E9 and
   M14 exist to name it, so the next instance is recognisable on sight.
